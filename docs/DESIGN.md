# Design decisions
**Dates**: stored as local-calendar Gregorian ISO strings (`YYYY-MM-DD`); converted to Ethiopian only for display/grouping (13 months, Pagume 5/6 days; round-trip tested 1900-2100). Device-local date, never UTC, so travel/time-zone changes never rewrite history.
**Goals**: `max_consecutive` (one set), `total_per_session`, `duration_seconds`, `sessions_per_week`, `total_sessions` are distinct metrics. Planning heuristic: a session total T ~ a max set of T/3 (labelled heuristic).
**Plan**: push-up level model. Prescription = ~1.8 x level working reps over 3-5 sets (never repeated max efforts). Every 4th week is a lighter week. Projection assumes +1 step per 2 sessions, capped at the goal. Original prescription is stored beside the current one with a reason.
**Progression (configurable, deterministic)**: pain -> no progression, review required. All sets met + effort <= 7 -> progress (successesRequired default 1). Finished but hard / partial -> maintain. Effort >= 9, <50% sets, or <70% avg reps -> reduce 10%; second in a row -> easier variation or reassess. Decisions are stored per session (unique) and never rewritten when a completed session is later edited.
**Missed**: past scheduled days become `missed` (pending review). Reschedule moves to the next free available day with no adjacent session (or after the plan end), never doubling; `originalDate` kept. Skip is neutral. 3+ misses in 14 days -> advice to reassess.
**Habit**: a session qualifies when finished with >= 50% of sets done. Weekly rule: qualifying sessions >= target minus skipped sessions that week; the current week never breaks a streak. Daily rule: only planned training days count; rest days and skips are neutral.
**Metrics**: total reps = sum of actual reps of done sets (reps and seconds never combined); best set = max single set; completion rate = completed / (planned days before today + completed today); future and rest days excluded; rescheduled sessions count once.
**Persistence**: SQLite, `schema_meta` version table, append-only migrations in a transaction. Sessions snapshot names/prescriptions; routine edits/deletes never alter history. UNIQUE(plan_day_id) prevents duplicate sessions; finishing is idempotent.
**Reminders**: pure computation (30-day horizon, stable ids) then cancel-all + schedule. Skipped/completed/moved sessions get none. Inexact delivery (no exact-alarm permission requested).
